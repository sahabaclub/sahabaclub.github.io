Before you start typing

What is wrong with these records. When somebody signs up, the club matches them against this contact list on their personal email address. Where we only ever recorded a person’s @sahabaclub.com mailbox and never a personal address, that match can never succeed — however many times they sign in. Filling the address in is what fixes it.

Two different situations, and the second is the one that catches people out. If they have not signed up yet, typing the address in is enough: the match runs automatically when they do. If they have already signed up, the match already ran and will not run again on its own — so saving here re-runs it for them straight away. The row tells you which case you are in before you type.

What this does not do. It does not claim the mailbox on their behalf. Claiming a Microsoft 365 account is the member’s own act — they confirm they know the password, or ask for a reset — and it starts a three-month licence clock the moment they do. What saving an address achieves is that the club now recognises them: the next time they open the site they are offered their mailbox, with the reset request as the alternative.

What this reading of “organise the data visibility” is

Every field the club holds about a person, how many records actually have it filled in, who is allowed to write it, and whether a spreadsheet may. The rows marked visibility are the ones that decide what other members can see.

This is not a per-person permission system, and deliberately so. Everyone who can open this page can already read every one of these fields straight from the database — the access rules are per table, not per field. A screen that offered to hide a column from a colleague would look like a control and be a preference. If per-field access is ever wanted it is a change to the database grants first and a screen second.

How importing works here

Nothing is written until you have read what would change. Choosing a file shows you a plan — which records would be created, which updated and exactly which fields, which clash with something a member wrote themselves, and which rows are rejected and why. Applying it is a separate button, and if anything about the plan has changed in between, it is refused rather than applied.

Start from an export. The file needs the id column (user_id for members) to know which person each row is. That is what lets you correct somebody’s email address rather than accidentally creating a second copy of them. A contacts file with no id is matched on the email address instead, and can only add people or fill in blanks — it cannot change an address.

An empty cell means “leave this alone”, never “erase this”. And a field a member wrote themselves — their bio, their headline, their skills — is never replaced by a spreadsheet without you saying so, row by row, in front of what they wrote.

Before you export

This is recorded. Taking a few thousand people’s email addresses and phone numbers out of the platform is not a page view, so who exported what, how many records and which columns is written down — and it cannot be turned off from here.

The default is what you are looking at, not the whole table. Filter the list on Browse & edit first and export that.

Excel and this data do not get on. The file is UTF-8 with a byte-order mark, so Arabic names open correctly rather than as mojibake. Phone numbers are the other half of the problem: left as plain text, Excel turns 0501234567 into 501234567 and 971504216499 into 9.71504E+11, silently. Tick the box below and those values are written in a form Excel shows exactly as stored — and this page strips the wrapper again when you import the file back, so the round trip changes nothing.

Every change to a person’s record

Recorded by the database itself rather than by this page, so a change made from the Supabase dashboard, by a scheduled job, or by any other part of the platform appears here too. Routine machine updates — engagement counters, avatar generation, the timestamp of the last campaign — are deliberately left out; this is a record of decisions.

A change whose author is the member themselves is shown as such. That is the record that says a bio was written by the person it is about.
